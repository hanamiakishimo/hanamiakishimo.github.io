  • Racket → 球拍、car → 汽车、cons → 施工、recursion → 递龟 等均为本篇故意保留的翻译事故 / 梗译。

1. define：大家已经研究决定了

球拍的第一件事，是钦点。

#lang racket

(define x 10)

这件事可以读成：

大家已经研究决定了，x 来当 10。

以后再出现 x，就照此办理。

(+ x 2)
; 12

当然，define 真正开始有蛤味，是到了过程这里。

先别用简写，直接把过程本体摆出来：

(lambda (x)
  (* x 2))

这是一个匿名过程。

它能工作，但暂时没有名字。

一个人的命运啊，当然要靠自我奋斗，但是也要考虑到历史的行程——这个过程自己也不知道，自己怎么就要被选到 double 去了。

于是：

(define double
  (lambda (x)
    (* x 2)))

中央都决定了：

你来当总书记。

在球拍这里就是：

你来当 double。

过程表示另请高明。

但是：

大家已经研究决定了。

于是 double 同志正式到岗。

(double 4)
; 8

这就是履职。

所以这里其实有两样东西，不要混在一起：

(lambda (x)
  (* x 2))

这是过程本体。

(define double ...)

这是钦点它担任 double。

球拍只是还提供了一种更短的写法：

(define (double x)
  (* x 2))

它和前面的：

(define double
  (lambda (x)
    (* x 2)))

表达的是同一件事。

所以 define 这一节目前只需要记住：

值           → 可以钦点名字
匿名过程     → 也可以钦点名字
名字被调用   → 正式履职

球拍这里还有一条规矩：

要干活的同志站最前面，参数排后面。

所以：

(+ 1 2)
(double 4)

而不是：

double(4)

double 先站出来，4 再跟上。

球拍不仅爱钦点，还坚持把领导放在最前面。 😭🐸

2. if：滋瓷不滋瓷？

球拍钦点完以后，记者开始提问。

(define 支持? #t)

(if 支持?
    '滋瓷
    '不滋瓷)
; '滋瓷

这基本就是：

你问我支持不支持？
我说支持。

if 不搞记者会，一次只处理一个二选一问题：

(if 条件
    滋瓷时怎么办
    不滋瓷时怎么办)

条件是真的：

滋瓷。

条件是 #f：

不滋瓷。

而且 if 自己会产生一个结果：

(define 表态
  (if 支持?
      '滋瓷
      '不滋瓷))

表态
; '滋瓷

大家已经研究决定了，现在正式表态。

什么叫“真”？

这里球拍开始表现出一点：

too simple, sometimes naive.

它的规则简单得离谱：

#f

是假。

除此之外，全算真。

(if 0 '滋瓷 '不滋瓷)
; '滋瓷

(if '() '滋瓷 '不滋瓷)
; '滋瓷

识得唔识得啊？

先记：

只有 #f 明确表示“不滋瓷”。

其他东西，球拍原则上：

滋瓷。

这个规定后面会酿成大祸。

3. cond：问来问去的问题

记者如果只问一句：

滋瓷不滋瓷？

if 足够。

但是记者开始追问：

这个呢？
那个呢？
那如果连任呢？
中央呢？
法律呢？

球拍逐渐：

问来问去的问题呀……

于是有了 cond。

(cond
  [(> x 0) '滋瓷正数]
  [(< x 0) '滋瓷负数]
  [else '另请高明])

它的工作方式就是从上往下不断被问：

第一项？
不滋瓷。

第二项？
滋瓷。

好了，不要再问了。

一旦第一条真的出现：

我就明确告诉你这点。

后面的分支不再执行。

所以：

(define x -3)

(cond
  [(positive? x) '正数]
  [(negative? x) '负数]
  [else '另请高明])
; '负数

到了第二条已经研究决定，后面不用继续开记者会。

else：另请高明

如果前面问了一圈，全都不是：

[else '另请高明]

意思就是：

这个问题当前各项方案都处理不了，另请高明。

注：这里把不同来源的蛤学语料库并表使用，纯属本篇梗化处理。

#<void>：无可奉告

然后事情开始危险起来。

刚才你问我，我可以说无可奉告，但你们又不高兴，我怎么办？

球拍里真的存在一种非常接近“说了，但是没给你一个有用值”的东西：

(displayln "无可奉告")

屏幕打印：

无可奉告

但表达式本身的值是 void。

可以写：

(define 回答
  (displayln "无可奉告"))

(void? 回答)
; #t

在把这个值明确打印出来的场景里，通常会写作：

#<void>

嘴上已经说了。

数据上：

还真的是一份“无可奉告”。

真正的事故在于：

#<void> 不是 #f

而我们上一节刚说了：

不是 #f？那就滋瓷。

#<void> 不是“完全没有返回”，而是一个表示“没有有意义结果”的正式值。

问题在于，球拍仍然把这份无可奉告视为真。

于是：

(cond
  [(displayln "无可奉告")
   '滋瓷]
  [else
   '另请高明])

实际逻辑是：

无可奉告
滋瓷

😭

记者：

所以到底支持不支持？

球拍：

无可奉告。

cond：

它没说 #f。

球拍：

那就是滋瓷。

这才是真正的 sometimes naive。

而这个 bug……不，这个语言特性，到后面的 polpot-sort 会被完整武器化：

display
↓
无可奉告
↓
#<void>
↓
不是 #f
↓
滋瓷这一支
↓
cdr
↓
继续
↓
不 cons
↓
人口持续减少

4. let / let*：临时研究决定

前面 define 是正式钦点：

(define x 10)

大家已经研究决定了，x 来当 10。

但有些事情没必要搞成长期任命。只在眼前这一小块里临时安排一下，就用 let。

(let ([x 10]
      [y 20])
  (+ x y))
; 30

可以理解成：

这两个问题，大家一起研究。
x，你来当 10。
y，你来当 20。
好，决定了。现在开始工作。

这里的关键是：

这一批是一起决定、一起上任的。

看一个会当场暴露问题的例子：

(define x 100)

(let ([x 10]
      [y (+ x 5)])
  y)
; 105

啊？

本轮明明刚刚写了：

[x 10]

怎么 y 算出来还是 105？

因为这批同志是一起上任的。

研究 y 的任命材料时，本轮这个 x = 10 还没上班。

所以它一抬头，抓到的是外面那个老 x = 100。

100 + 5
→ 105

各份右边材料仍然按顺序计算；但在这些材料都算完以前，本轮新人谁都还没正式上任。

你不要把还没上任的同志先拿来开展工作。

😭

let 更像：

名单一起上会
↓
一起研究决定
↓
一起生效
↓
开始工作
↓
会议结束，临时职务撤销

let*：一个一个研究决定

如果要求：

前一个已经决定，后一个根据前面的决定继续研究。

那就不是 let，而是 let*。

(let* ([x 10]
       [y (+ x 5)]
       [z (* y 2)])
  (+ x y z))
; 55

这个过程就很有味了。

先研究 x。

大家已经研究决定了，x = 10。

好了。

那么下面研究 y。

x 的问题已经决定了，所以 y 可以根据 x 来。

于是：

y = 15

继续：

y 也决定了。
下面研究 z。

于是：

z = 30

最后：

各项已经研究决定，开始执行。

所以 let* 就是：

研究一个
↓
决定一个
↓
前一个立即上任
↓
后一个据此继续研究

一句话区分：

let
= 一批人一起上会，一起钦点

let*
= 一个一个钦点；
  前一个已经决定，
  后一个根据既成事实继续研究

而且两者都只是临时班子。

出了这一块：

(let ([x 10])
  x)

x
; unbound identifier

会议散了，x 同志已经不担任有关职务。

所以这一节最后可以收成一句：

define 是“大家已经研究决定了”；
let 是“这批一起研究决定”；
let* 是“前一个已经决定，下面继续研究下一个”。

5. list / cons / car / cdr：汽车、施工，以及剩下的 comrades

球拍终于开始处理名单。

'：以上内容作为材料，不作进一步研究

前面已经老出现这个东西：

'滋瓷
'a
'(a b c)

本笔记决定把 ' 理解成：

以上内容作为材料，不作进一步研究。

比如 a 单独出现，球拍可能还要问：

a 同志是谁？

但是：

'a

意思就是：

不要查了。材料上就写着 a。

整张名单也一样：

'(a b c)

原样归档，不逐个传唤。

至于：

'()

名单打开一看：

没人。

技术上补一句就够：'x 是 (quote x) 的简写；这里的 a 是一个 symbol。

要是现场施工一张名单，也可以：

(list 'a 'b 'c)
; '(a b c)

好了，现在正式有一批 comrades：

(define comrades
  '(a b c d))

这是一个 list：

'(a b c d)

car：汽车先把一个同志拉走

(car comrades)
; 'a

car 取得列表的第一个元素。

本笔记决定不采用任何合理翻译。

car：汽车。

于是：

(a b c d)
 ↑
汽车把 a 同志拉走了

现在单独研究 a。

至于被汽车拉走以后去哪里——

暂时可以理解成接受有关去城市化安排，
后面甚至可能坐上钢叉。

先不要问钢叉为什么能坐。

球拍的交通体系后面会越来越不正常。

cdr：剩下的 comrades

汽车把第一个同志拉走以后：

(cdr comrades)
; '(b c d)

这就是：

剩下的 comrades。

所以一个 list 最重要的拆法其实极其简单：

car → 当前同志
cdr → 剩下的 comrades

或者：

(a b c d)

car ─────→ a
cdr ─────→ (b c d)

这件事后面非常重要。

因为递归处理 list 的基本动作几乎就是：

拉走一个同志，
然后继续研究剩下的同志。

cons：施工，把同志重新编回名单

如果 a 同志研究完以后还需要保留：

(cons 'a '(b c d))
; '(a b c d)

cons 的正常含义当然不是施工。

但是：

cons → 施工

已经决定了，不再另请高明。

于是：

汽车拉走 a
↓
研究
↓
施工
↓
a 被重新编回 comrades

也就是：

(cons 当前同志 剩下的同志)

重新构造一张名单。

没有施工会怎样

现在问题来了。

如果：

汽车拉走一个同志
↓
研究
↓
不施工
↓
直接继续处理 cdr

那这个同志就不会出现在新名单里。

技术上只是：

没有 cons 回去。

但从名单管理角度看：

完成了一次清洗。

比如：

(cdr '(a b c d))
; '(b c d)

(cdr '(b c d))
; '(c d)

(cdr '(c d))
; '(d)

(cdr '(d))
; '()

于是 comrades 的数量：

4
↓
3
↓
2
↓
1
↓
0

剩下的同志越来越少。

组织纯洁性不断提高。

组织本身逐渐不存在。

6. recursion：递龟 🐢

球拍处理完一个同志以后，往往还有：

剩下的 comrades。

怎么办？

交给下一只龟。

(define (copy-list xs)
  (cond
    [(null? xs)
     '()]

    [else
     (cons (car xs)
           (copy-list (cdr xs)))]))

表面上这叫 recursion。

本笔记统一译为：

递龟。

因为整个过程就是：

🐢₁：我处理当前同志。
     剩下的同志交给下一只龟。

                ↓

🐢₂：我处理当前同志。
     剩下的同志交给下一只龟。

                ↓

🐢₃：我处理当前同志。
     ……

一只龟把工作递给下一只龟。

故名：

递龟。

每只龟只负责眼前这一位

还是这段：

(cons (car xs)
      (copy-list (cdr xs)))

拆开就是：

(car xs)

汽车把当前同志拉出来。

(cdr xs)

剩下的 comrades。

(copy-list (cdr xs))

当前同志的问题我已经研究了。
剩下的同志，请下一只龟研究。

下一只龟也是这么想的。

于是形成了一个非常稳定的甩锅体系：

当前同志我管
剩下同志下级管

🐢

null?：龟终于发现已经没人了

递龟不能无限递。

所以必须有：

[(null? xs)
 '()]

某一只龟收到名单以后打开一看：

'()

沉默。

已经没有剩下的同志了。

于是：

递龟工作结束。

这个条件就是 base case。

也可以叫：

龟到底了。

如果没有它：

🐢 → 🐢 → 🐢 → 🐢 → 🐢 → …

大家一直把不存在的同志往下移交。

最终不是去城市化，是龟灾。

正常递龟为什么同志还能回来？

因为有：

cons

当前同志虽然被汽车拉走研究，但研究完成以后：

(cons 当前同志
      剩下同志的处理结果)

施工队会把她重新编回名单。

所以正常递龟是：

汽车拉走
↓
研究
↓
把剩下的同志交给下一只龟
↓
下一只龟处理完回来
↓
施工
↓
当前同志重新入列

龟一路往下递，施工一路往上盖。

最后名单还能回来。

如果龟只往下递，不往回施工呢？

现在把 cons 拿掉：

(define (mysterious-work xs)
  (cond
    [(null? xs)
     '()]

    [else
     (mysterious-work (cdr xs))]))

流程：

🐢 当前同志？
   已处理。

   剩下的同志？
   交给下一只龟。

下一只：

🐢 当前同志？
   已处理。

   剩下的同志？
   再交给下一只龟。

但是从头到尾：

没有施工。

于是：

(a b c d)
   ↓
(b c d)
   ↓
(c d)
   ↓
(d)
   ↓
()

龟确实完成了全部工作。

同志也确实一个没回来。

这是递龟第一次显露出它在波波体系中的潜力。

7. 高阶函数：去城市化工作现代化

前面的名单工作基本依靠手工：

(car comrades)
(cdr comrades)
(cons ...)

汽车负责拉走当前同志，递龟负责把剩下的 comrades 继续往下移交，施工队负责把需要保留的同志重新编回名单。

工作虽然能做，但效率很低。

于是球拍决定推进现代化。

lambda：无名英雄同志

(lambda (x)
  (* x 2))

这是一个没有名字的过程。

没有正式钦点，没有职务名称，但拿到任务照样干活：

((lambda (x)
   (* x 2))
 5)

; 10

所以：

lambda = 无名英雄同志

如果组织上后来决定正式任命：

(define double
  (lambda (x)
    (* x 2)))

无名英雄同志就被钦点为 double。

map：地图

(map
  (lambda (x)
    (* x 2))
  '(1 2 3 4))

; '(2 4 6 8)

地图发下来以后，全体同志按图改造：

1 → 2
2 → 4
3 → 6
4 → 8

原来四名 comrades。

改造结束以后仍然四名。

所以：

map：全体同志按图改造，原则上一个不少。

目前组织工作还比较文明。

filter：过滤

然后出现了：

(filter positive?
        '(3 -1 4 -5 2))

; '(3 4 2)

filter 会逐个审查：

3   → 符合 → 重新施工
-1  → 不符合 → 不施工
4   → 符合 → 重新施工
-5  → 不符合 → 不施工
2   → 符合 → 重新施工

所以它其实就是第 5 节那套东西的现代化版本：

符合条件
→ cons 回新名单

不符合条件
→ 不 cons
→ 从新名单消失

本笔记因此决定：

filter = 过滤 / 去城市化设备

例如：

(filter even?
        '(1 2 3 4 5 6))

; '(2 4 6)

原有六名同志。

工作完成以后：

剩余三名 comrades。

其他同志的情况：

无可奉告。

foldl：最后只留一份汇总材料

filter 至少最后还留下了一张名单。

foldl 连名单都可以不要。

(foldl + 0 '(1 2 3 4))
; 10

会议纪要一开始是：

0

然后同志一个一个来：

1 来了 → 1
2 来了 → 3
3 来了 → 6
4 来了 → 10

最后个人名单不重要了。

桌上只剩：

汇总材料：10

所以本章先把 foldl 记成：

从左往右收材料，一边收，一边改那份累计结果。

不过球拍这里又有一个很容易把人绊倒的机关流程。

如果自己写无名英雄同志：

(foldl
  (lambda (x acc)
    ...)
  初始值
  xs)

递进来的顺序是：

当前同志 x
累计材料 acc

同志先进去，材料后进去。

不要按别家机关的流程猜。😭

比如：

(foldl cons '() '(1 2 3 4))
; '(4 3 2 1)

名单当场倒过来了。

所以别把 foldl 背成什么“从左边加括号”。

先认这条流水线就够：

从左边来一个同志
↓
拿当前累计材料一起处理
↓
得到新的累计材料
↓
继续

for：佛

然后是：

(for ([x '(1 2 3 4)])
  (displayln x))

本笔记继续拒绝正常翻译：

for = 佛

佛不搞一次性处理。

佛讲究一个一个渡：

渡 1
渡 2
渡 3
渡 4

如果渡完以后还要重新形成名单：

(for/list ([x '(1 2 3 4)])
  (* x 10))

; '(10 20 30 40)

于是：

for/list：佛渡完以后重新登记 comrades。

佛也可以带审查：

(for/list ([x '(1 2 3 4 5)]
           #:unless (even? x))
  (* x 10))

; '(10 30 50)

工作记录：

1 → 渡 → 10 → 登记
2 → 不渡 → 不登记

8. 排序动物园：冒泡、插队、斯大林，以及波波

前面已经有：

cdr     → 剩下的 comrades

8.1 Bubble sort：冒泡，同志之间正常调座位

先从相对文明的开始。

(define (bubble-pass xs)
  (cond
    [(or (null? xs)
         (null? (cdr xs)))
     xs]

    [(> (car xs)
        (car (cdr xs)))
     (cons (car (cdr xs))
           (bubble-pass
            (cons (car xs)
                  (cdr (cdr xs)))))]

    [else
     (cons (car xs)
           (bubble-pass (cdr xs)))]))

例如：

(bubble-pass '(4 2 3 1))
; '(2 3 1 4)

这一趟发生的事情其实很朴素：

4 和 2
→ 座次不对
→ 交换

4 和 3
→ 座次不对
→ 再交换

4 和 1
→ 又交换

于是 4 一路被推到最后。

没有同志消失。

没有去城市化。

只是不断调整座位。

冒泡：组织内部正常人事调动。

完整冒泡可以重复若干趟：

(define (bubble-sort xs)
  (define (repeat ys n)
    (if (zero? n)
        ys
        (repeat (bubble-pass ys)
                (sub1 n))))

  (repeat xs (length xs)))

(bubble-sort '(4 2 3 1))
; '(1 2 3 4)

这里最重要的是：

car/cdr
→ 拿出相邻同志研究

cons
→ 调整完以后重新施工

递龟
→ 继续研究后面的同志

属于比较正常的组织工作。

8.2 Insertion sort：简单插入，也就是安排插队

再来简单插入排序。

先写一个“把新同志插进已经安排好的队伍”的函数：

(define (insert x xs)
  (cond
    [(null? xs)
     (list x)]

    [(<= x (car xs))
     (cons x xs)]

    [else
     (cons (car xs)
           (insert x (cdr xs)))]))

例如：

(insert 4 '(1 3 5 7))
; '(1 3 4 5 7)

过程非常像：

4 来了。

1：
你排我后面。

3：
你也排我后面。

5：
好了，你排我前面。

于是：

(1 3 5 7)
    ↑
   插入 4

得到：

(1 3 4 5 7)

整个排序：

(define (insertion-sort xs)
  (cond
    [(null? xs)
     '()]

    [else
     (insert (car xs)
             (insertion-sort (cdr xs)))]))

(insertion-sort '(4 2 3 1))
; '(1 2 3 4)

这里非常有递龟精神：

当前同志
↓
先别急

剩下的同志
↓
交给递龟排好

排好以后
↓
当前同志再找自己的座位

所以：

简单插入：前面的座次已经研究决定，新同志根据既成事实安排座位。

有一点 let* 的味。

8.3 Stalin sort：不调整队伍，调整同志

然后动物园突然开始不对劲。

给定：

'(1 4 2 5 3 8)

如果要求递增，正常排序会想办法重新排列。

Stalin sort 不这样想。

它的思路是：

队伍没有问题。
不符合队伍方向的同志有问题。

于是：

1   留
4   留
2   破坏递增 → 清洗
5   留
3   破坏递增 → 清洗
8   留

结果：

'(1 4 5 8)

可以写成：

(define (stalin-sort xs)
  (cond
    [(null? xs)
     '()]

    [else
     (cons (car xs)
           (stalin-from (car xs)
                        (cdr xs)))]))

(define (stalin-from last xs)
  (cond
    [(null? xs)
     '()]

    [(>= (car xs) last)
     (cons (car xs)
           (stalin-from (car xs)
                        (cdr xs)))]

    [else
     (stalin-from last
                  (cdr xs))]))

注意这里的关键差别。

通过审查：

(cons (car xs) ...)

施工。

没有通过：

(stalin-from last
             (cdr xs))

没有 cons。

于是：

符合方向
→ 重新编回名单

不符合方向
→ 继续研究剩下的同志
→ 当前同志不再出现

这已经正式接上第 5 节的：

不施工 = 从新名单消失。

所以 Stalin sort 的一句话版本就是：

排序太麻烦了，不如清洗掉造成无序的同志。

😭

9.1 老办法：汽车、施工、递龟全员出动

先不用 filter 和 map。

汽车一辆一辆拉，施工队该回来就回来，龟该往下递就往下递：

(define (prepare-comrades xs)
  (cond
    [(null? xs)
     '()]

    [(>= (car xs) 0)
     (cons (* (car xs) 2)
           (prepare-comrades (cdr xs)))]

    [else
     (prepare-comrades (cdr xs))]))

工作记录：

car
→ 拉出当前同志

>= 0
→ 审查

通过
→ ×2
→ cons
→ 重新施工

不通过
→ 不 cons
→ 递龟继续处理剩下的 comrades

所以：

(prepare-comrades comrades)
; '(8 2 10 0)

座次再交给前面的简单插入：

(define prepared
  (insertion-sort
    (prepare-comrades comrades)))

prepared
; '(0 2 8 10)

最后，连汇总材料都自己递龟：

(define (sum-list xs)
  (if (null? xs)
      0
      (+ (car xs)
         (sum-list (cdr xs)))))

于是：

(sum-list prepared)
; 20

工作完成。

汽车、施工队、递龟，一个都没缺席。

9.2 组织工作现代化

但是组织上看完以后认为：

手工递龟效率太低，应推进现代化。

于是同一项工作重新招标：

(let* ([clean
        (filter
          (lambda (x)
            (>= x 0))
          comrades)]

       [doubled
        (map
          (lambda (x)
            (* x 2))
          clean)]

       [ordered
        (insertion-sort doubled)]

       [total
        (foldl + 0 ordered)])

  (list ordered total))
; '((0 2 8 10) 20)
